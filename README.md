# Hard-Insert

VST3 / CLAP плагин аппаратного инсерта для FL Studio (и любой другой DAW) под Windows.
Плагин **сам открывает аудиокарту** (ASIO или Windows Audio), отправляет звук трека на выбранные
физические выходы, принимает возврат с выбранных физических входов и возвращает его на трек.
Задержка петли измеряется пингом и сообщается DAW для компенсации (PDC).

```
трек FL ──► Hard-Insert ──► выход карты N ──► компрессор ──► вход карты M ──► Hard-Insert ──► трек FL
```

## Возможности

- **Send L/R, Return L/R** — любые физические каналы карты.
- **Force Mono (L+R)/2** — стерео-трек с моно-источником идёт через один физический канал (экономия каналов).
- **Input Trim / Output Trim** — ±24 дБ, с индикаторами уровня отправки и возврата.
- **Measure Latency (ping)** — один импульс через петлю (кабель вход↔выход или сам прибор),
  поиск пика, отчёт задержки в DAW. Показывает также уровень пинга и **полярность** (если прибор переворачивает фазу).
- Измеренная задержка сохраняется **в проекте**, отдельно для каждой частоты дискретизации.
- **Safety buffer (Auto)** — буфер между потоком DAW и потоком карты; входит в PDC.
- Одна карта на все экземпляры плагина: второй экземпляр (например, для сайдчейна) работает параллельно без конфликтов.

## Установка

Скачать артефакт `Hard-Insert-windows-x64` из последней сборки в **Actions** и скопировать:

- `Hard-Insert.vst3` → `C:\Program Files\Common Files\VST3\`
- `Hard-Insert.clap` → `C:\Program Files\Common Files\CLAP\`

## Настройка в FL Studio

1. Вставить Hard-Insert в слот микшера трека.
2. Вкладка **Audio Device**: выбрать тип и устройство (см. «Какой драйвер выбрать»).
   Частота дискретизации должна совпадать с частотой FL.
3. Вкладка **Insert**: выбрать Send L/R (выходы на прибор) и Return L/R (входы с прибора).
   Для моно-источника включить **Force Mono** — используются только Send L / Return L.
4. Соединить петлю и нажать **Measure Latency (ping)**. PDC обновится автоматически.
5. При изменении буфера карты или FL задержка в режиме Auto пересчитывается; после смены карты/буфера стоит измерить пинг заново.

### Какой драйвер выбрать

ASIO обычно рассчитан на одно приложение. Если FL уже держит ASIO-драйвер карты:

1. **ASIO той же карты** — работает, если драйвер многоклиентский. Если плагин сообщает об ошибке открытия — вариант 2 или 3.
2. **Windows Audio** (или *Windows Audio (Low Latency Mode)*) **на той же карте** — большинство карт позволяют это параллельно с ASIO.
   Задержка выше, но она входит в PDC и измеряется пингом.
3. FL переключить на **FL Studio ASIO**, а плагину отдать **нативный ASIO** карты.

Важно использовать **ту же физическую карту**, что и FL: у разных карт разные тактовые генераторы,
и петля будет периодически пересинхронизироваться (видно в строке состояния: *Resyncs*).

## Как держится точная задержка

Поток DAW и поток карты связаны двумя lock-free FIFO. Суммарное заполнение FIFO неизменно,
поэтому каждый сэмпл возвращается ровно через **P + D** сэмплов (P — safety buffer, D — путь через карту и прибор).
При пропусках (дроп-ауты FL или карты) недостающие кадры заменяются тишиной, а опоздавшие отбрасываются —
тайминг не плывёт. Если время потеряно насовсем, петля перезапускается с тем же P, и PDC остаётся верным.

Это проверяется симуляцией `tests/port_test.cpp` в каждой сборке CI: неровные блоки FL, джиттер,
WASAPI- и ASIO-буферы, одиночные и серийные дроп-ауты DAW и карты — каждый пинг обязан вернуться ровно через P + D.

## Сборка

GitHub Actions (`windows-latest`, MSVC + Ninja). Локально:

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```
